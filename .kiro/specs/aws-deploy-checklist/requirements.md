# Requirements Document

## Introduction

Operational checklist for provisioning and deploying the PAGA MVP environment on AWS. This spec covers the execution of infrastructure stack creation, backend deployment, frontend deployment, and end-to-end validation — following the runbook at `docs/runbook.md`. The output is a self-contained task list with exact commands using generic placeholders, executable from a Windows + PowerShell workstation targeting Amazon Linux 2023 on EC2.

## Glossary

- **Operator**: The person executing the deploy checklist from their local machine
- **Checklist**: The ordered list of verification and execution steps that compose this deploy procedure
- **Stack**: An AWS CloudFormation stack representing a logical group of infrastructure resources
- **Parameter Store**: AWS Systems Manager Parameter Store, used for storing secrets as SecureString parameters
- **EC2 Instance**: The Amazon Linux 2023 virtual machine that hosts the API, PostgreSQL, and Nginx
- **SPA Bucket**: The S3 bucket serving the Angular single-page application via CloudFront
- **CloudFront Distribution**: The CDN distribution that fronts both the SPA (S3) and the API (EC2 origin)
- **Publish Artifact**: The output of `dotnet publish` containing the compiled API ready for deployment
- **Migration Script**: An idempotent SQL file generated by EF Core that brings the database schema up to date
- **Health Endpoint**: `GET /health` — the only unauthenticated API endpoint used to verify the backend is running

## Requirements

### Requirement 1: Prerequisites Verification

**User Story:** As an Operator, I want to verify all prerequisites before starting the deploy, so that I avoid failures mid-process.

#### Acceptance Criteria

1. THE Checklist SHALL include a step to verify AWS CLI v2 is installed by running `aws --version`.
2. THE Checklist SHALL include a step to verify the `palaia` AWS profile is configured by running `aws sts get-caller-identity --profile palaia`.
3. THE Checklist SHALL include a step to verify .NET 10 SDK is installed by running `dotnet --version`.
4. THE Checklist SHALL include a step to verify Node.js 20+ is installed by running `node --version`.
5. THE Checklist SHALL include a step to verify Angular CLI is installed by running `ng version`.
6. THE Checklist SHALL include a step to create the three required Parameter Store secrets (`/paga/jwt-key`, `/paga/db-password`, `/paga/admin-password`) as SecureString using `aws ssm put-parameter` with `--profile palaia`.
7. THE Checklist SHALL include a step for the Operator to record their public IP in CIDR notation (`<your-ip>/32`), the EC2 key pair name, and a globally unique S3 bucket name.
8. THE Checklist SHALL present all `aws` commands with the flag `--profile palaia`.

### Requirement 2: Network Stack Provisioning

**User Story:** As an Operator, I want to create the Network stack first, so that subsequent stacks can import its VPC and subnet exports.

#### Acceptance Criteria

1. THE Checklist SHALL include the exact `aws cloudformation create-stack` command for `paga-prod-network` with parameters `Environment=prod`, `VpcCidr=10.0.0.0/16`, `SshCidr=<your-ip>/32`, and `CloudFrontPrefixListId=pl-3b927c52`.
2. THE Checklist SHALL include the `aws cloudformation wait stack-create-complete` command immediately after the create command.
3. IF the Network stack creation fails, THEN THE Checklist SHALL instruct the Operator to check the CloudFormation events using `aws cloudformation describe-stack-events`.

### Requirement 3: IAM Stack Provisioning

**User Story:** As an Operator, I want to create the IAM stack after the Network stack, so that roles and policies are available for the EC2 instance.

#### Acceptance Criteria

1. THE Checklist SHALL include the exact `aws cloudformation create-stack` command for `paga-prod-iam` with parameters `Environment=prod`, `ArtifactBucketArn`, `FrontendBucketArn`, and `CloudFrontDistributionArn`, including `--capabilities CAPABILITY_NAMED_IAM`.
2. THE Checklist SHALL note that `CloudFrontDistributionArn` may use a wildcard ARN (`arn:aws:cloudfront::<account-id>:distribution/*`) on the first deploy.
3. THE Checklist SHALL include the `aws cloudformation wait stack-create-complete` command for `paga-prod-iam`.

### Requirement 4: EC2 Stack Provisioning

**User Story:** As an Operator, I want to create the EC2 stack after IAM, so that the instance can assume the provisioned role.

#### Acceptance Criteria

1. THE Checklist SHALL include the exact `aws cloudformation create-stack` command for `paga-prod-ec2` with parameters `Environment=prod`, `InstanceType=t3.micro`, and `KeyPairName=<your-key-pair-name>`.
2. THE Checklist SHALL include the `aws cloudformation wait stack-create-complete` command for `paga-prod-ec2`.
3. WHEN the EC2 stack creation completes, THE Checklist SHALL include the `aws cloudformation describe-stacks` command to retrieve and record the EC2 public IP from the stack outputs.

### Requirement 5: Frontend Stack Provisioning

**User Story:** As an Operator, I want to create the Frontend stack last, so that it can reference the EC2 public IP as an origin.

#### Acceptance Criteria

1. THE Checklist SHALL include the exact `aws cloudformation create-stack` command for `paga-prod-frontend` with parameters `Environment=prod`, `BucketName=<your-spa-bucket-name>`, and `Ec2PublicIp=<ec2-public-ip>`.
2. THE Checklist SHALL include the `aws cloudformation wait stack-create-complete` command for `paga-prod-frontend`.
3. WHEN the Frontend stack creation completes, THE Checklist SHALL include the command to retrieve the CloudFront domain from the stack outputs.
4. THE Checklist SHALL instruct the Operator to record the CloudFront domain for use in backend CORS configuration and validation steps.

### Requirement 6: Backend Publish and Transfer

**User Story:** As an Operator, I want to publish the .NET API and transfer it to EC2, so that the backend is ready to run on the instance.

#### Acceptance Criteria

1. THE Checklist SHALL include the `dotnet publish backend/src/Paga.Api -c Release -o ./publish` command executed from the repository root.
2. THE Checklist SHALL include the `dotnet ef migrations script --idempotent` command to generate `./publish/migrations.sql`.
3. THE Checklist SHALL include the `scp` command to transfer the publish folder contents to `/opt/paga/api/` on the EC2 instance, using the placeholder `<path-to-private-key.pem>` and `<ec2-public-ip>`.

### Requirement 7: Database Migration on EC2

**User Story:** As an Operator, I want to run the migration script on the EC2 instance, so that the database schema is up to date before the API starts.

#### Acceptance Criteria

1. THE Checklist SHALL include the `ssh` command to connect to the EC2 instance.
2. WHEN connected to the EC2 instance, THE Checklist SHALL include the command to read the DB password from Parameter Store using `aws ssm get-parameter`.
3. THE Checklist SHALL include the `psql` command to run the idempotent migration script against the `paga` database.

### Requirement 8: Backend Environment Configuration and Service Start

**User Story:** As an Operator, I want to configure environment variables and start the API service, so that the backend runs with correct secrets and settings.

#### Acceptance Criteria

1. THE Checklist SHALL include commands (on EC2) to read `/paga/jwt-key`, `/paga/db-password`, and `/paga/admin-password` from Parameter Store.
2. THE Checklist SHALL include the command to write the `/opt/paga/api/.env` file with the connection string, JWT key, admin seed email, admin password, and CORS allowed origin (using the CloudFront domain placeholder).
3. THE Checklist SHALL include `sudo chmod 600 /opt/paga/api/.env` to restrict file permissions.
4. THE Checklist SHALL include `sudo systemctl restart paga-api.service` followed by `sudo systemctl status paga-api.service` to verify the service started.
5. IF the service fails to start, THEN THE Checklist SHALL instruct the Operator to inspect logs with `sudo journalctl -u paga-api.service -n 50 --no-pager`.

### Requirement 9: Frontend Build and Deployment

**User Story:** As an Operator, I want to build the Angular SPA and deploy it to S3, so that users can access the frontend via CloudFront.

#### Acceptance Criteria

1. THE Checklist SHALL include the `ng build --configuration production` command executed from the `frontend/` directory.
2. THE Checklist SHALL include the `aws s3 sync` command to upload `frontend/dist/frontend/browser/` to the SPA bucket with the `--delete` flag and `--profile palaia`.
3. THE Checklist SHALL include the commands to retrieve the CloudFront distribution ID and create an invalidation for `/*`.
4. THE Checklist SHALL note that cache invalidation takes 1-5 minutes to propagate.

### Requirement 10: End-to-End Validation

**User Story:** As an Operator, I want to validate the full deployment, so that I confirm the system is operational before considering the deploy complete.

#### Acceptance Criteria

1. THE Checklist SHALL include a health check via CloudFront: `curl -s https://<cloudfront-domain>.cloudfront.net/api/health` expecting `{"status":"Healthy"}`.
2. THE Checklist SHALL include a step to open the CloudFront URL in a browser and verify the Angular login page renders.
3. THE Checklist SHALL include a `curl` command to `POST /api/auth/login` with the admin credentials, expecting a 200 response with `accessToken`, `refreshToken`, and `expiresIn`.
4. THE Checklist SHALL include a CORS preflight check using `curl -I -X OPTIONS` with `Origin` and `Access-Control-Request-Method` headers, expecting `Access-Control-Allow-Origin` in the response.
5. WHEN all validation steps pass, THE Checklist SHALL declare the deployment complete.
